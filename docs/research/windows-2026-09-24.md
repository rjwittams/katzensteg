# Katzensteg on Windows: feasibility (2026-09-24)

Research for the Windows end-to-end map (Wheelhouse). Host: Beaufort, Windows 11
26200, Zig 0.16.0 (winget), VS 2022 Build Tools. Base revision `83c1897`.
luchs is excluded from this work.

## What Katzensteg does

A Zig/C launcher, injected runtime and terminal graphics engine (`termscene`).
The launcher starts an SDL2/SDL3 app (sometimes GL, Vulkan or Metal) with a
preload library (`LD_PRELOAD` / `DYLD_INSERT_LIBRARIES`) intercepting roughly
60–85 SDL functions per SDL version. It composes frames and emits Kitty
graphics (raw RGBA APC, `t=f` files, or `t=s` POSIX shared memory) to
`/dev/tty`, or as JSONL batches over a socket/pipe to a host (Katzensteg WM,
pi, Claude, or a Jackstay CPU publisher). Terminal key/mouse reports feed back
into SDL through a shared input model.

Cleat's ghostty-VT engine parses the Kitty stream and re-serves images to
viewers including Wheelhouse. Jackstay is an optional frame connector;
`build.zig` panics on non-macOS/Linux.

## Mechanism mapping

| Mechanism | Windows analogue | Recommendation |
| --- | --- | --- |
| `LD_PRELOAD` + `dlsym(RTLD_NEXT)` SDL interposers (`interpose_*.c`, `real_sdl*.c`) | `SDL_DYNAMIC_API` / `SDL3_DYNAMIC_API`: SDL loads our DLL, which takes the real jump table and substitutes `ks_` wrappers; works with static SDL | **Use.** No injection, low AV risk. |
| macOS import rebinding (`darwin_rebinder`) | IAT patching / Detours | Fallback only for apps with dynapi disabled |
| Launch-time injection | Suspended `CreateProcess` + `DetourCreateProcessWithDllEx`; `CreateRemoteThread`+`LoadLibrary` | Avoid: Defender/EDR heuristics, signing. `AppInit_DLLs` is dead. |
| GL capture | `wglSwapBuffers` hook | Cover via SDL's GL swap through dynapi |
| Vulkan layer | Explicit layer via `VK_LAYER_PATH` + `VK_INSTANCE_LAYERS` | Portable; avoid implicit registry layers |
| Metal hook | DXGI `Present` vtable hook | Out of scope |
| POSIX `t=s` shm (consumer unlinks; producer polls for name removal) | Named `CreateFileMapping` | No "name disappears" signal on Windows; needs explicit ack/lease. Start with `t=f`. |
| fork/exec, process groups, signals, termios, `/dev/tty`, fd `poll` | Job Objects, `CONIN$`/`CONOUT$` with VT modes, `WaitForMultipleObjects`, libxev IOCP, `AF_UNIX` or named pipes | Bulk of the work |

## ConPTY probe (observed)

Probe sources are in `docs/research/conpty-probe/`.

- **Inbox ConPTY** (kernel32 `CreatePseudoConsole`, flags 0, as Cleat uses):
  silently drops Kitty APC and sixel DCS. Unknown OSC (1337, 5522) passes
  through verbatim up to at least 4 MiB. Flag `0x8` (passthrough) is accepted
  but changes nothing.
- **NuGet `Microsoft.Windows.Console.ConPTY` 1.24.260710001** (bundled
  `conpty.dll` + `OpenConsole.exe`): APC, DCS and OSC pass through unchanged
  and in order. It sends `CSI 1t` / `CSI c` queries at startup.
- Not verified: input direction (Kitty keyboard, SGR-pixel mouse 1016, pixel
  size replies).

Going through Cleat is a blocker only while Cleat uses inbox ConPTY. Fix:
bundle `conpty.dll` as Windows Terminal and WezTerm do, or use the JSONL
hosted-batch side channel.

## Terminals

- Wheelhouse via Cleat: best target (ghostty-VT supports Windows; image
  rendering is renderer-neutral uishell code; D3D11 image path unverified).
- WezTerm: Kitty graphics plausible, `t=f` likely; untested.
- Windows Terminal 1.24: sixel only, no Kitty graphics.
- Anything behind inbox ConPTY: no.

## Build (observed)

- `zig build test`: 11 of 29 suites pass (jackstay with Jackstay off,
  termscene-protocol, config, log, render-batch-protocol, attach-protocol,
  terminal-batch-applier, wm-command-input, wm-cli, wm-event,
  launcher-context). launcher-profiles: 1 fail, 2 crashes (no Windows
  preload/`VK_LAYER_PATH` in profiles). launcher-destination expects `/`
  joins. The rest fail to compile.
- `zig build`: every artifact fails. `src/platform/` is POSIX (fd ints,
  termios, `pipe2`, `SIG.KILL`, `pollfd`, `Permissions.fromMode`, `environ`);
  `shared_memory.zig` uses `shm_open`/`mmap`; `env_scrub.c` needs `dlfcn.h`;
  `whiskers_client`, `direct_tty`, `wm/client`, `listener`, `http` assume fd
  sockets. `build.zig` has no Windows library branch. Lazy evaluation means
  more errors surface layer by layer.
- Commit `456ea9b` on this branch adds Windows `platform/time.zig` (QPC) and
  `sync.zig` (SRWLOCK/condition variables); Linux/macOS cross-compiles still pass.
